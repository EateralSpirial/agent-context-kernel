# Bootstrap Output Contract

This file owns the mandatory output contract for every project bootstrapped by Agent Context Kernel. The bootstrap derives all additional structure from project evidence.

## Required Objects

### Project Context Entry

**The target repository has one root `AGENTS.md`.**

The entry explains how the project's context system unfolds, carries compact repository-wide execution gates, and routes tasks to the narrowest relevant standards, skills, product contracts, plans, risk owners, and evidence. It remains an onboarding surface and lets canonical owners carry complete definitions.

### Project Skill Library

**The target repository has one project-local skill library.**

Use the agent runtime's established project skill location. Use `.agents/skills/` when the repository has no coherent convention. The library contains discoverable, trigger-specific procedures for recurring, high-risk, fragile, or project-specific work. Additional skills appear when project evidence justifies their maintenance cost.

### Context Evolution Skill

**The project-local skill library contains exactly one `evolve-project-context` skill.**

This skill is the sole procedural owner for constructing, consolidating, relocating, simplifying, validating, and iterating the project's context system. It applies all four kernel principles and governs how context owners, routes, wording, change states, metadata, and semantic regression evidence evolve together.

The skill's project-specific method covers these responsibilities:

1. establish the desired context outcome and its reason;
2. locate the current primary owner, dependent routes, local applications, and semantic duplicates;
3. preserve meaning that is costly to recover, improves material judgment, or protects a risk boundary;
4. write durable meaning once and align routes, local applications, metadata, links, and tests in the same change;
5. coordinate current truth, explicit target state, implementation evidence, and closure through the four change states;
6. validate the resulting route from a capable new agent's perspective.

Other context files describe current project truth or route to this procedure. Task-specific skills apply it when their work changes context-worthy behavior.

## Derived Structure

The bootstrap may establish standards, product documentation, plans, risk owners, evidence indexes, module contracts, and context regression tests according to project scale and evidence.

A `.standards/` directory is a useful default when the project needs reusable architecture, module, submodule, database, configuration, risk, or codebase rules across several task classes. Smaller projects can place a compact set of stable rules in existing canonical owners. Every derived object receives a clear scope, owner, route, and reason to persist.

## Completion

The bootstrap completes when the three required objects exist, route to one another coherently, apply the four principles, and support a representative cold-start task. The project-local `evolve-project-context` skill then owns routine context-system evolution; the bootstrap skill remains available for first construction, major reconstruction, and independent audit.
