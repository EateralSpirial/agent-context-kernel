# Evolve Project Context

This skill is the sole project method for changing this repository's context system. Canonical context files describe current meaning; this skill owns the procedure that evolves their ownership, routes, form, and validation.

## Read First

Read `AGENTS.md`, both canonical references under `skills/project-context-bootstrap/references/`, and the narrowest owner affected by the task. Inspect implementation or executable evidence to the depth required to verify current truth.

## Operating Premise

Prepare compact onboarding for a capable future agent. Preserve project-specific meaning that improves judgment, costs meaningful effort to recover, or protects a material boundary. Let implementation, tests, installer behavior, and Git history carry ordinary mechanics and process evidence.

## Method

1. State the intended context outcome, affected owner, and reason the change earns permanence.
2. Locate the current canonical owner, dependent routes, local applications, generated projections, and semantically parallel descriptions.
3. Change principle meaning in `kernel-principles.md`, required-output meaning in `bootstrap-contract.md`, bootstrap procedure in `SKILL.md`, usage in `docs/usage.md`, and installer mechanics in `scripts/install.py` according to their existing ownership.
4. Establish the intended canonical context before implementation when durable capability, behavior, ownership, or procedure changes.
5. Express shared guidance through the desired state, responsible owner, relevant condition, action, and effect. Use precise local constraints where literal or safety boundaries need them.
6. Write each durable meaning through one owner, reduce other occurrences to routes or local applications, and align metadata, links, wrappers, public orientation, and semantic tests in the same change.
7. Run `python -m unittest discover -s tests`, inspect the final diff as a fresh capable agent, and confirm that every modified route reaches its owner directly.

## Change States

- **Aligned:** owners, procedures, implementation, and tests express the accepted repository state.
- **Context ahead:** one canonical change owner expresses the intended target while dependent implementation is being aligned.
- **Implementation ahead:** implementation or evidence has advanced and the missing context owner is being established.
- **Diverged:** competing durable intentions are resolved at their canonical owner before dependent work expands.

## Acceptance

Accept the change when the repository remains self-hosting under the bootstrap output contract, the primary owner is easy to reach, shared prose earns its context cost, stale meanings close in the same change, installers preserve one implementation owner, and all regression tests pass.
